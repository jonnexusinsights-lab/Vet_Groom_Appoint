# DEFINITION_OF_DONE

## Purpose

This checklist defines when a task is actually complete.

## Done checklist

A task is done only when:

- The requested scope is implemented.
- Assumptions are documented where requirements were incomplete.
- Architecture alignment is preserved.
- Tests were added or updated when relevant.
- Lint and type checks pass when applicable.
- Documentation was updated when relevant.
- Dependency/license impact was reviewed.
- No hidden out-of-scope expansion was introduced.
- Risks or follow-up items are explicitly noted.

## Additional criteria for business-critical changes

Also required for scheduling, permissions, payments, exports, or auth-related work:

- Edge cases reviewed.
- Regression risk considered.
- Auditability preserved where needed.
- Security implications considered.
